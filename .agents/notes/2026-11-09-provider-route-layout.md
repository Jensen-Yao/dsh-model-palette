# Provider route layout

The configuration browser groups configured routes by endpoint hostname. Routes produced by a Responses/Chat protocol split therefore stay beneath one heading, show aggregate model counts, and expose protocols as compact chips instead of repeating raw API ids on every card. Routes without a shared endpoint remain singleton groups, so unrelated catalog providers are never collapsed. Provider search includes display names, ids, endpoint hosts, raw protocols, and friendly labels.

Status chips filter all providers, routes with a missing runtime credential, and routes with enabled free synchronization. The protocol select displays Responses, Chat, and Messages with their endpoint paths while retaining the DSH wire values. Anthropic Messages keeps the existing /messages probe with x-api-key and anthropic-version; the OpenAI-only Responses/Chat comparison controls are disabled for that wire. Verification covers singleton isolation, endpoint grouping, aggregate counts, protocol ordering and labels, the cross-platform media output test, and a browser fixture containing Responses and Chat branches on one fixture endpoint.
