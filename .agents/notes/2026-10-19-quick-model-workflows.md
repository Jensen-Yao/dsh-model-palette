# Quick model workflows

Named quick profiles store an exact provider, model and optional reasoning effort in origin-scoped browser storage. Omitting effort keeps provider-default selection distinct from an explicit level. Profiles never include credentials or provider configuration. Invalid stored records are filtered; duplicate ids/names are ignored, labels are bounded to forty characters, and twelve ordered profiles are retained. Same-name saves update the existing slot; explicit rename refuses a collision. Storage failures are reported without showing a false success. Browser storage events and an in-page event keep composer seats synchronized.

The first three profiles appear beside the composer and use Alt+Shift+1/2/3. Reordering changes these assignments. Missing models retain their profile and disable its button; a keyboard attempt reports the unavailable selection without selecting another model. Delete supports one in-panel undo; a conflicting restored name is refused rather than overwriting a newly created profile.

Previous-model history belongs to one mounted model directory. Observed provider/model transitions record the complete prior selection. Reasoning-only changes update the remembered current selection without displacing the previous model. Failed requests never advance history. All activation paths share compatibility/reasoning preparation, a synchronous in-flight guard and native directory selection. Locked or externally selecting seats refuse shortcut requests. These actions do not send prompts or test-generation requests.

The configuration editor registers its current leave guard with the palette. Closing or navigating to a different panel checks dirty state; transitions between the editor and its template catalog retain the mounted component. Mutating settings blocks departure until the write settles. Browser unload keeps its independent dirty-state guard.

Search retains literal matching as the highest score and adds NFKC normalization and punctuation-insensitive matching. Explicit free/reasoning terms inspect the advertised suffix/efforts; @provider tokens constrain the provider independently of model names. A nonempty search ranks stronger matches before favorites. Reset clears query, provider, quick filter, capability and sort together.

Validation covers stored-data filtering, exact effort retention, naming collisions, ordering and count limits, normalized searches and semantic/provider terms. The keyless browser fixture records selection attempts and can hold, reject or lock them. Browser checks exercise persisted quick profiles, switch-back, reordered shortcuts, failed/concurrent/locked selections, unavailable models, delete/undo and dirty-editor navigation. Real DSH provider requests remain outside these keyless checks.
